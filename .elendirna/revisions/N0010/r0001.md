## 운영 발견 3건 — 누적 (2026-05-07)

vault validate 실측 중 발견된 3개 항목. 기능별로 분리된 issue가 아니라 cmd-validate 영역 누적이라 한 묶음.

### 1. `--fix`가 자동 수정을 보고하지만 파일에 반영되지 않음
- 증상: `elf validate --fix` 실행 시 stdout에 "1개 항목 자동 수정됨" 출력. 그러나 두 번째 `elf validate` 실행에서 동일 warning 재출현.
- 재현: N0058 frontmatter↔manifest title 불일치 케이스에서 관찰 (2026-05-07)
- 의심: dry-run 흔적이 남았거나, write 단계에서 silent fail. 또는 frontmatter 파서가 unclosed quote를 fix할 때 파일 write를 누락
- 우선순위: 중. `--fix`가 사용자 신뢰 손상 — "수정됐다" 보고 후 변화 없음은 silent corruption 의심 유발

### 2. dangling inline ref false-positive — 문서화 entry 안의 example까지 검사
- 증상: N0010(이 entry) note.md에 illustrative `→ see N0099` 문자열이 있음. 실제 broken link 아님 — 그저 cmd-validate가 무엇을 잡는지 보여주는 example
- validator는 이를 dangling ref로 잡음
- 옵션:
  - (a) example 표기를 명백히 reserved 번호(N9999)로 바꿈 — 즉시 회피
  - (b) validator가 fenced code block / inline code / blockquote 안의 N#### 패턴은 무시
  - (c) `<!-- elf:ignore -->` ignore comment 메커니즘
- 권고: (b) — example을 마크다운 코드 블록으로 옮기면 자연스럽게 격리. cmd-validate 문서화 가치 보존

### 3. frontmatter quote escape 차이로 인한 title 불일치
- N0058: frontmatter `title: "Release Summary: v0.5 "Multi-vault & Attachments""` 에서 내부 따옴표 escape 처리 모호. manifest는 escape된 `""` 두 개, frontmatter는 unclosed quote처럼 보임
- title에 따옴표 포함 시 frontmatter는 single-quote 또는 backslash escape 권장. validator 메시지가 시각적으로 같아 보이는 두 문자열을 비교해 혼란 — diff에 escape 표현을 명시하면 사용자 진단 빨라짐
