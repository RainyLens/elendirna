## Delta

## CLI 우선 구현 계획 (2026-04-24)

목표: MCP 업로드 프로토콜 전에, 로컬 파일 경로 기반 `entry attach/detach`를 먼저 제품화한다.

### 현재 기준점

- `manifest.sources: Vec<String>` 이미 존재.
- `validate`는 `assets/` dangling/미등록 검사 이미 수행.
- 따라서 MVP는 새로운 저장소 구조 도입 없이도 구현 가능.

### 범위 (Phase 1: CLI MVP)

1. 명령 추가
- `elf entry attach <ID> <FILE_PATH> [--label <TEXT>] [--copy-name <NAME>] [--json]`
- `elf entry detach <ID> <ASSET_KEY> [--json]`
- `elf entry assets <ID> [--json]` (목록 확인용, 선택이지만 권장)

2. 저장 규칙
- 파일은 `/.elendirna/assets/`로 복사
- `ASSET_KEY`는 기본적으로 `{entry_id}_{slugified_original_name}`
- 동일 key 충돌 시 `_2`, `_3` suffix
- 실제 참조는 `manifest.sources`에 key 문자열로 추가/삭제

3. 이벤트 기록
- `entry.attach`, `entry.detach`를 `sync.jsonl`에 append
- payload에는 `entry_id`, `asset_key`, `size`, `mime`(가능 시) 포함

4. validate 연동
- 기존 validator 로직 재사용
- `--full` 플래그는 Phase 2로 미룸 (해시 검증)

### 구현 파일 단위 계획

1. `src/cli/entry.rs`
- `EntryCommand`에 `Attach`, `Detach`, `Assets` 추가
- args struct + run 함수 추가
- 파일 접근/복사 + manifest update + sync event 기록

2. `src/cli/help.rs`
- command surface에 신규 명령/인자 문서 반영

3. `src/vault/ops.rs` (선택)
- CLI/MCP 공용화를 대비해 `asset_attach/asset_detach/asset_list` 코어 추출 가능
- 단기적으로는 CLI 내부 구현으로 시작해도 무방

4. `src/cli/tests.rs`
- attach 성공: assets 파일 생성 + manifest.sources 반영
- detach 성공: manifest.sources 제거 + 파일 정리(참조 없음 시)
- 중복 attach key 충돌 처리
- 잘못된 entry/file path 오류 코드

### 비범위 (명시적 제외)

- 청크 업로드, upload session, resume/retry
- SHA-256 저장 및 full integrity verify
- CAS(content-addressed) dedup
- 원격 HTTP 인증/권한

### Phase 2 예고 (CLI 강화)

- `manifest.sources`를 구조체 배열로 확장 (`key`, `orig_name`, `mime`, `size`, `sha256`, `added_at`)
- `elf validate --full`에서 해시 재계산
- 대용량 파일 정책 (warn/hard-limit)

### 수용 기준 (DoD)

1. `entry attach` 후 `entry show --json`에서 `sources`에 key가 보인다.
2. `entry detach` 후 해당 key가 `sources`에서 제거된다.
3. `validate` 경고 없이 왕복 가능(attach -> detach).
4. `cargo test` 기존 테스트 + 신규 첨부 테스트 통과.

### 결론

MCP/HTTP 미래 설계를 해치지 않으면서도, 실무에서 바로 쓸 수 있는 첨부 기능은 CLI path 기반으로 먼저 완성한다. 이후 MCP는 chunk 업로드 레이어를 별도로 올린다.
