## 첨부파일 MVP 세부 정책: sync warning과 affix 기반 asset key 충돌 해결 (2026-04-24)

첨부파일 CLI/MCP MVP의 세부 정책을 정리한다.

### sync event 실패는 warning

`entry attach/detach`에서 파일 복사/삭제 및 `manifest.sources` 갱신이 성공했으나 sync event 기록만 실패한 경우, 전체 작업을 실패시키지 않는다.

이유:
- sync는 보조 활동 로그이며 source of truth가 아니다.
- 첨부파일 기능의 핵심 source of truth는 assets 파일과 manifest.sources다.
- 따라서 sync 실패는 작동상 핵심 문제라기보다 보조 기록 누락이다.

API/CLI는 warning을 반환하거나 출력한다.

### asset key 충돌 처리

기본 key는 `{entry_id}_{slugified_original_name}`로 생성한다.
동일 key가 이미 있으면 affix 숫자를 붙인다.

예:
- `N0021_diagram.png`
- `N0021_diagram_2.png`
- `N0021_diagram_3.png`

서버가 최종 key를 결정하고, API result에 반환한다.

권장 응답 필드:
```json
{
  "ok": true,
  "entry_id": "N0021",
  "asset_key": "N0021_diagram_2.png",
  "stored_filename": "N0021_diagram_2.png",
  "source_path": "D:\\work\\diagram.png",
  "original_name": "diagram.png",
  "collision": true,
  "size": 12345,
  "mime": "image/png",
  "warnings": []
}
```

장점:
- 클라이언트/AI가 충돌 해결 규칙을 직접 구현할 필요가 없다.
- 이후 detach/list/show에서는 반환된 `asset_key`만 사용하면 된다.
- 같은 원본 파일명을 여러 번 첨부해도 결과가 명확하다.

주의:
- `--copy-name <NAME>`이 있는 경우에도 동일 충돌 규칙을 적용한다.
- key 생성은 path traversal을 막기 위해 파일명만 사용하고 directory component는 제거한다.
- 최종 key는 assets 디렉터리 내부에만 resolve되어야 한다.
