## Delta

## 보완: 세션 맥락 기록은 sync 계층으로 유도

모델별 vault 쓰기 성향 차이는 버그라기보다 도구 자유도에서 자연스럽게 발생하는 현상으로 본다. 다만 entry revision에 세션 전체 맥락이 과도하게 섞이면 revision의 역할이 흐려지고, `sync.jsonl`/session log의 존재 이유도 약해진다.

따라서 기본 유도 규칙은 다음처럼 잡는다.

- entry revision: 해당 entry의 의사결정, 설계 변경, 지식 delta를 기록한다.
- sync_record: 이번 세션에서 어떤 맥락이 오갔고 어떤 entry를 건드렸는지 기록한다.
- 긴 대화 맥락을 entry에 직접 붙이는 대신, 필요한 경우 sync/session index를 통해 복원한다.
- review/synthesis 요청처럼 관련 맥락을 entry에 남기는 것이 유효한 경우에도, revision에는 요약된 판단과 결론만 남기고 대화 흐름 자체는 sync에 둔다.

이 정책은 Codex식 integrative recorder를 부정하는 것이 아니라, 통합 기록의 저장 위치를 분리하는 방향이다. 향후 `session_start` 또는 MCP tool description에 이 규칙을 짧게 주입하면 모델별 쓰기 편차를 줄일 수 있다.

SQLite activity index는 이 정책과 잘 맞는다. `sync.jsonl`은 append-only source of truth로 유지하고, sqlite에는 session/activity projection을 만들어 AI가 raw sync 파일을 직접 읽지 않고도 최근 세션 맥락을 조회하게 한다.
