## 실제 통증 지점 재진단 (2026-04-16)

r0001~r0003에서 설계한 '격리 + 명시적 참조' 방향은 유효하나,
실제 문제가 더 구체적으로 파악됨.

### 근본 원인: 서버 시작 시점의 vault 고정

ElfMcpServer는 vault_root: PathBuf 하나를 시작 시 고정함 (src/mcp/mod.rs:50).
elf serve --mcp vault 결정 순서 (src/cli/serve.rs:24):
--vault → ELF_VAULT → find_vault_root(CWD) → global 자동 생성

| 환경 | CWD | 결과 |
|---|---|---|
| CLI | 프로젝트 디렉터리 | local vault 선택 (정상) |
| Claude Desktop | Desktop 앱 자체 CWD | global vault 선택 또는 자동 생성 |

Desktop은 자체 프로세스 CWD로 서버를 시작하므로, 서버 입장에서 프로젝트 경로를 알 방법이 없음.
사용자가 관찰한 'CLI MCP는 local을 읽는다'는 현상은 이 구조의 자연스러운 결과임.

### 두 가지 실사용 충돌 시나리오

1. Desktop → local 접근: Desktop 기본값(global)으로 서버가 열려 있으나, 특정 프로젝트의 local vault를 참조해야 할 때
2. Local 작업 중 → global 참조: local vault에서 작업하면서, global vault의 설계 원칙/패턴을 비교 참조해야 할 때

두 경우 모두 '현재 열려있는 vault 외 다른 vault를 tool 호출 단위로 지정'할 수단이 없어 발생.

### 수정 방향 확정 (2단계)

1단계 (즉시): session_start 응답에 현재 활성 vault 경로(vault_root)와 안내 힌트 추가.
에이전트가 세션 시작 시 '어느 vault가 열려 있는지' 명시적으로 인지하게 함.

2단계 (N0038 핵심): 조회 tool(entry_list, entry_show, bundle, query)에
vault: Option<String> 파라미터 추가. 서버는 primary vault를 유지하되,
tool 호출 단위로 override 허용. 값 해석: 절대경로 → 'local' → 'global' → config alias 순.

→ see N0037 (함께 수정 대상으로 관리)
