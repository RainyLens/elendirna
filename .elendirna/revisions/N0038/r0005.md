## Delta

## vault 파라미터 최종 설계 확정 (2026-04-16)

### 전제 확인
Claude Desktop은 대화(세션)마다 별도 PID로 elf.exe를 실행함이 확인됨.
따라서 프로세스 인메모리 상태는 세션 간 격리가 보장됨.

### config.toml alias 역할 재정의
멀티vault를 의도적으로 구성하려는 power user 전용.
MCP tool에서 동적 등록 금지 — 에이전트가 config.toml을 쓰는 경로를 원천 차단.
(config.toml은 디스크 공유 자원이므로 쓰기 자체가 오염 경로)

### 인메모리 'local' 등록 — 핵심 설계
각 세션(프로세스)에서 session_start(local_vault=<path>) 를 호출하면
해당 프로세스 메모리에만 local → <path> 를 등록함.
프로세스 종료 시 자동 소멸. 다른 세션에 노출 없음.

### vault 파라미터 해석 순서 (tool 공통)
1. 'global'  → ~/.elendirna/ (예약어, 불변)
2. 'local'   → 이 프로세스에 session_start로 등록된 경로 (없으면 에러)
3. 절대경로  → 그대로 사용 (일회성 인라인 접근)
4. alias     → config.toml [vaults] 조회 (의도적 멀티vault 전용)

### API 변경
- session_start(local_vault: Option<String>) 파라미터 추가
  → 등록 + 세션 시작을 한 번에 처리, 별도 set_local_vault tool 불필요
- entry_list, entry_show, bundle, query, revision_add, entry_new, entry_status
  → vault: Option<String> 파라미터 추가 (위 해석 순서 적용)
