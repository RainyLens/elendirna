## Desktop MCP 실행 컨텍스트 관찰 보강 (2026-04-24)

사용자 관찰을 반영하여 Desktop/MCP 환경 차이를 보강함.

Claude Desktop의 MCP 서버는 사실상 데스크톱 앱이 서비스처럼 띄운 고정 실행 컨텍스트에서 동작한다. 따라서 사용자가 특정 repo 작업을 하고 있더라도 MCP 서버 입장에서는 repo CWD가 자연스럽게 전달되지 않으며, 기본적으로 global 기준으로 동작하는 경향이 있다.

또한 정확한 내부 구현은 추가 확인이 필요하지만, Claude Desktop은 MCP 설정/옵션을 `%LOCALAPPDATA%` 이하의 가상/관리 폴더 쪽으로 복사해 사용하는 것으로 관찰됨. 이 경우 `elf serve --mcp`가 보는 CWD와 사용자가 생각하는 작업 폴더가 분리되므로, local vault 자동 탐색이 기대대로 작동하지 않을 수 있다.

반면 Codex Desktop의 세션은 각 폴더 또는 repo 기준으로 작업 컨텍스트가 잡히며, 현재 관찰된 세션에서는 MCP가 `D:\code_etc\elendirna` local vault를 정상 primary로 잡았다. 따라서 Claude Desktop에서 보였던 "local 작업 중 global 기준 MCP" 현상이 Codex Desktop에서는 동일하게 재현되지 않았다.

결론: 이 이슈는 단순한 vault 탐색 버그라기보다, MCP host가 서버 프로세스를 어떤 작업 디렉터리와 설정 복사 정책으로 실행하느냐에 따라 달라지는 host-specific 문제다. `session_start`의 출처 표시와 향후 `local_vault` 등록/호출 단위 `vault` override는 특히 Claude Desktop류 host에서 중요하다.
