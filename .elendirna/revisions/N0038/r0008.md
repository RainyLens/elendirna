## "그럼에도 불구하고" 완화 계층으로서의 현재 조치 (2026-04-24)

사용자 해석을 반영하여 현재 조치의 성격을 명확히 함.

Claude Desktop처럼 MCP host가 서버를 global 기준 고정 컨텍스트에서 실행하거나, 설정/옵션을 별도 관리 폴더로 복사해 사용해 repo CWD 의도가 전달되지 않는 문제는 host-specific 실행 모델에서 비롯된다. `elf` 쪽에서 CWD 탐색 규칙만 고쳐서는 이 차이를 완전히 제거할 수 없다.

지금까지의 조치는 이 host 차이를 없애는 근본 해결이라기보다, "그럼에도 불구하고" 피해를 완화하는 계층이다.

- MCP 응답에 `vault`, `vault_kind`를 포함하여 에이전트가 실제 출처를 확인할 수 있게 함
- 현재 구현이 서버 시작 시 `vault_root` 하나에 고정되므로, 같은 세션 안에서 local/global 자료가 임의로 섞일 가능성은 낮음
- `session_start`에서 현재 활성 vault를 명시적으로 보고하여 세션 초기에 잘못된 primary를 감지할 수 있게 함
- 향후 `local_vault` 등록과 tool 호출 단위 `vault` override는 host-specific CWD 단절을 우회하는 명시적 제어면으로 작동해야 함

즉 현재 상태는 "host 실행 모델 차이로 primary vault가 어긋날 수 있다"는 문제를 완전히 해결하지는 못하지만, 출처 표시와 단일 primary 고정 덕분에 혼합·오염 가능성은 상당히 완화된 상태다.
