## Claude Desktop code vs Claude Code vault 수신 차이 관찰 (2026-04-24)

사용자 관찰을 추가함.

Claude Desktop의 `code` 실행 맥락은 Claude Code와 다르게 repo-local 작업 컨텍스트만 넘기는 것이 아니라, vault까지 global 기준으로 받아오는 것으로 관찰됨. 즉 같은 "코드 작업"이라도 host별로 MCP/vault primary가 다르게 잡힐 수 있으며, Claude Desktop code에서는 사용자가 repo 작업을 의도해도 global vault가 기본 컨텍스트로 들어올 가능성이 더 크다.

이 관찰은 기존 r0007~r0010의 host-specific CWD 단절 문제를 더 강화한다. Claude Code는 CLI/프로젝트 CWD에 가까운 실행 모델이라 local vault 의도가 비교적 잘 보존되는 반면, Claude Desktop code는 Desktop 앱의 관리 실행 컨텍스트와 global vault 결합이 더 강하게 나타난다.

따라서 향후 설계에서는 단순히 "Desktop MCP는 CWD를 잃을 수 있다"가 아니라, "Desktop code host는 vault 컨텍스트 자체를 global로 주입/수신할 수 있다"는 케이스를 명시적으로 다뤄야 한다.

설계 함의:
- session_start 응답의 `vault`, `vault_kind`, 향후 `vault_resolution` 확인은 Claude Desktop code에서 특히 필수다.
- `local`은 host CWD 추론이 아니라 session-local 등록 또는 명시 path 기반으로만 신뢰해야 한다.
- Claude Code와 Claude Desktop code를 같은 MCP host 동작으로 가정하면 안 된다.
