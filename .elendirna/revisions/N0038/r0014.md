## Delta

## sudo 패턴 (stateless escalation) 명확화 + codex/gemini 검증 (2026-04-30)

r0009~r0013에서 누적된 multi-vault 호출 정책을 사용자의 sudo 비유로 단순화·통합. 새 정책이 아니라 기존 라인의 자연스러운 정리.

### 사용자 명확화
"sudo"라고 말했지만 **timestamp-style stateful escalation은 없음**. 호출당 둘 중 하나로 충족:
- (a) 명시적 parameter — `vault='global'`, `vault='<alias>'`, `vault='<absolute>'`
- (b) confirm 절차 — destructive/bulk만

session_start(vault=...)도 stateful default 변경이 아니라 "이번 호출의 view 선택"으로 축소.

### 단계형 가드 (codex 권고 + 사용자 명확화)
| 작업 | 메커니즘 |
|---|---|
| read non-local | (a) parameter |
| write non-local (entry_new/revision_add/sync_record) | (a) parameter + 응답에 escalated_write:true |
| destructive/bulk (validate, detach, bulk migration) | (a) parameter + (b) confirm_*=true |

### 두 모델 일치
- 빠뜨려 local에 쓰는 건 global 오염보다 safe-fail (codex/gemini 일치)
- escalated_write 플래그 + 시각적 강조 태그(🚨)면 충분, confirm 매번 강요는 과함
- CWD 기반 fallback 판정은 OK이되 valid local vault 판정 필요 (codex)
- alias도 호출당 명시 (사용자 정의에 자동 부합)

### codex 추가 보강
- **read-then-write drift**: `bundle(vault='global')`로 읽고 이어 `revision_add()`에서 vault 빠뜨리면 local에 씀. write 응답에 target_vault 강조 필요
- **valid local 판정**: 디렉토리 있고 manifest/index 깨진 경우를 "없음"으로 취급하면 위험. 판정:
  - valid `.elendirna` 발견 → local active
  - 없음 → global fallback 가능 + 응답에 fallback:true + warning AND
  - 있음 but invalid → fallback 금지, 오류
- **alias는 fallback 대상 아님**: 등록되어 있어도 미지정 호출의 fallback 대상은 alias가 아니라 global. alias는 명시 접근 전용
- **멀티 에이전트 동시 write**는 sudo 정책과 별개 — sqlite transaction/append-only log 영역

### gemini 추가 보강
- alias 등록 자체가 사용자 의도 표명이므로 호출 시 별도 confirm 없음 (사용자 정의의 (a) parameter만으로 충족, codex와 양립)
- ignore_fallback marker 파일은 지금은 over-engineering, 미래 옵션
- 시각적 태그가 plain flag보다 인지 효과 큼
