## 구현 정책 보강: vault 생략/명시 분기 (2026-04-24)

N0038 r0009의 정책을 구현 관점으로 보강함.

`resolve_tool_vault(explicit, local, primary)`는 다음 의미를 가져야 한다.

### explicit 없음
1. 세션 local vault가 등록되어 있으면 local 사용
2. 없으면 primary vault 사용
3. primary vault는 서버 시작 시 기존 fallback 룰(`--vault`/`ELF_VAULT`/CWD 탐색/global fallback)로 이미 결정된 값
4. 응답에는 항상 resolved `vault`, `vault_kind` 포함

### explicit 있음
1. `global` → global vault
2. `local` → 세션 local vault. 미등록이면 에러
3. 절대경로 → 해당 vault root. 유효하지 않으면 에러
4. alias → config `[vaults]`에서 resolve. 미등록이면 에러
5. explicit resolve 실패 시 primary/global 등으로 자동 fallback 금지

이 구조는 편의성과 안전성을 함께 만족한다. 기본 호출은 local-first 흐름을 유지하고, 예외적으로 global 또는 다른 alias가 필요할 때만 사용자가 명시한다. 모든 응답은 실제 resolved vault를 포함하므로 host-specific CWD 차이나 설정 복사 문제를 사후 확인할 수 있다.
