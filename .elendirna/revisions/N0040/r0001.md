## 문제

MCP tool(`entry_list`, `bundle`, `query` 등)의 응답에 **vault 출처 정보가 없다.**
AI는 응답만 보고 어느 vault에서 온 데이터인지 구분할 수 없다.

## 실제 발생한 사례 (2026-04-16)

- MCP가 전역 vault를 읽고 있었으나 AI는 로컬 vault로 착각
- 전역 vault의 Coater 관련 entry를 로컬 entry로 잘못 분류
- `entry_new`, `revision_add` 호출이 의도와 다른 vault(전역)에 기록됨
- MCP로 생성된 N0025는 전역 vault에 잘못 기록된 상태

## 위험성

**읽기 혼선:** AI가 잘못된 컨텍스트로 추론 → 판단 오류
**쓰기 혼선:** 엉뚱한 vault에 entry/revision 생성 → vault 오염
**보안 이슈:** 격리되어야 할 vault 간 데이터가 무단으로 혼입될 수 있음

## 해결 방향

MCP 응답 모든 곳에 `vault` 필드 추가:
- `entry_list` → 각 entry에 `vault: "/path/to/.elendirna"` 또는 `vault: "local"/"global"` 표시
- `bundle`, `entry_show` 등 동일하게 적용
- AI가 호출 전 vault 컨텍스트를 명시적으로 확인할 수 있어야 함
