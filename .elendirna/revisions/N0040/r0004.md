## Delta

## 추가 사례: Codex에서 global 지식이 local vault에 기록된 반대 방향 오염 (2026-04-24)

N0055 롤백 과정에서 확인된 MCP 오작동/운영 사고 사례를 추가한다.

### 발생 내용

- 사용자는 TDalsa 카메라 Dark/White Calibration 절차를 전역 지식으로 남기려는 의도를 갖고 있었다.
- 그러나 Codex Desktop 세션의 MCP primary는 `D:\code_etc\elendirna` local vault였다.
- `entry_new` / `revision_add` / `sync_record`가 local vault에 실행되어 N0055가 로컬 프로젝트 기록으로 생성되었다.
- 이후 사용자가 "전역 지식으로 지시한 부분이 로컬에 기록된 듯하다"고 지적했고, N0055 entry/revision 디렉터리를 제거한 뒤 `validate`로 index를 재생성하여 롤백했다.

### 의미

기존 N0040의 대표 사고는 MCP가 global을 읽거나 쓰고 있는데 AI가 local로 착각한 경우였다. 이번 사례는 반대 방향이다.

- Claude Desktop류 host: repo 작업 의도인데 global primary가 잡힐 수 있음.
- Codex Desktop류 host: repo local primary가 잘 잡히기 때문에, 전역 지식 기록 의도까지 local로 흡수될 수 있음.

즉 문제는 단순히 global fallback이 위험하다는 것이 아니라, **사용자의 쓰기 의도(write intent)와 MCP가 resolve한 vault가 다를 수 있다**는 점이다.

### 설계 함의

출처 표시만으로는 부족하다. 모든 write tool에는 최소한 다음 중 하나가 필요하다.

- 사용자가 전역 지식/로컬 프로젝트 지식 중 어디에 쓰려는지 명시할 수 있는 `vault` 파라미터
- `entry_new`, `revision_add`, `sync_record` 응답에 resolved vault뿐 아니라 write intent와 비교 가능한 `vault_resolution` 메타데이터
- global/external write confirm뿐 아니라, local write라도 사용자가 global을 의도한 정황이 있으면 확인을 유도하는 agent protocol

### 운영 원칙 보강

AI는 사용자가 "전역 지식", "개인 지식", "일반 절차", "프로젝트와 무관한 지식"처럼 말한 경우, 현재 local vault에 곧바로 쓰지 말고 `session_start`의 `vault_kind`와 사용자 의도를 대조해야 한다.

- local 프로젝트 산출물: local vault에 기록
- 개인/전역 지식: global vault 또는 명시된 별도 vault에 기록
- 불분명한 경우: 쓰기 전 확인
