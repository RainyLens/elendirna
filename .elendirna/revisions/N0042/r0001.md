## Delta

## v0.4.5: Multi-Vault Context Awareness 개선 계획

### 1. 현상 분석
현재 Multi-Vault(Local/Global) 환경에서 Agent가 "지금 어느 저장소에 쓰는 중인가?"를 망각하거나 혼동함.
- **원인 A**: `vault_kind`가 "local" 또는 "global"로만 표시되어, 여러 Local 프로젝트 간 구분이 안 됨.
- **원인 B**: `vault_info()`가 단순히 경로 일치 여부로만 `kind`를 판단하여, `~/.elendirna/` 하위 구조와 불일치할 가능성.
- **원인 C**: 개별 도구 호출(`bundle`, `show`)의 응답 데이터 내부에 Vault 식별자가 없어, 데이터가 많아지면 컨텍스트에서 사라짐.

### 2. 해결 전략: Vault Identity 명시화 (Vault Alias)

#### P0: Vault Alias 시스템 강화
- `ElfMcpServer` 구조체에 `vault_alias` 필드 추가.
- `elf serve --mcp` 시작 시, 현재 `vault_root`가 `~/.elendirna/config.toml`의 어느 `[vaults]` 별칭에 해당하는지 자동 매핑.
- 모든 MCP 응답의 `vault_kind` 필드를 **`vault_name` (Alias)**으로 대체하거나 병행 표기.
  - 예: `{ "vault_name": "elendirna", "vault_kind": "local" }`

#### P0: session_start Seed Prompt 고도화
- `session_start` 도구가 반환하는 `instructions`에 현재 Vault의 Alias와 경로를 최상단에 고정 노출.
- "You are currently working in the **[elendirna]** vault (local project)." 와 같은 명시적 문장 주입.

#### P1: Contextual Branding
- `bundle` 및 `entry_show` 응답의 JSON 구조 내에 `source_vault` 정보를 엔트리 메타데이터로 포함.
- AI가 읽는 마크다운 본문 상단에 `[Source: VaultAlias]` 주석을 옵션으로 삽입.

### 3. 우선순위 (Execution Order)
1. **P0 (Critical)**: `vault_name` (Alias) 정보를 MCP 응답에 전역 주입.
2. **P0 (Critical)**: `session_start` 프롬프트에 현재 Vault 정체성(Identity) 명시.
3. **P1 (High)**: `config.toml` 역조회 로직 구현 (Path -> Alias).
4. **P2 (Normal)**: `elf help --json` 및 에러 메시지에 Vault 명칭 일관성 적용.
