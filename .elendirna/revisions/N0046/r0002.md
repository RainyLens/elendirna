## Delta

## "방금 전 작업"의 정의에 관한 고찰
Undo의 대상이 되는 '마지막 작업'의 범위를 확정하기 위한 세 가지 모델:

1. **Global Chronological Model (전역 시간축)**
   - Vault 내의 모든 엔트리를 통틀어 가장 최근에 생성된 파일/로그 1건.
   - "방금 한 실수"를 바로잡는 데 가장 직관적임.
   - 슬롯 소멸 원칙을 적용하기 가장 깔끔함.

2. **Per-Entry Stack Model (엔트리별 스택)**
   - 특정 엔트리의 최신 리비전 1건.
   - `elf undo <id>` 형태로 호출.
   - 여러 엔트리를 넘나들며 작업할 때 유연하지만, '실수 교정'보다는 '이력 관리'의 성격이 강해짐.

3. **Session Transaction Model (세션 트랜잭션)**
   - 가장 최근의 `sync_record`와 그에 묶인 모든 리비전들.
   - AI 세션 단위의 작업 취소에 적합.
   - 취소 범위가 커서 의도치 않은 데이터 손실 위험 존재.

## 잠정 결론
Elendirna의 철학(계보의 엄중함)을 고려할 때, **Model 1(전역 시간축)**을 기본으로 하되, 사용자가 명시적으로 엔트리를 지정할 경우에만 **Model 2**로 동작하게 하는 하이브리드 방식 혹은 **Model 1의 엄격한 적용**이 타당해 보임.

"한 번 Undo하면 슬롯 제거"라는 원칙을 지키기 위해서는 전역적으로 단 하나의 'Undoable Action'만 추적하는 시스템이 가장 안전함.
