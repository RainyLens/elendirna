## 승인 대상
순수 MCP 서버 사용 맥락만 가진 Codex 관점에서 제시된 elf MCP 평가를 승인 가능한 제품/설계 피드백으로 채택한다.

핵심 판단은 다음과 같다.

- elf MCP는 단순 메모장이 아니라 Codex의 세션 간 작업 맥락을 복원하는 장기 기억 계층으로 유효하다.
- `session_start → query/bundle → revision_add → sync_record` 흐름은 이전 작업의 이유, 결정 배경, 다음 행동 방향을 회복하는 데 실용적이다.
- dogfooding 단계의 실험적 메모 도구를 넘어, 업무 전용 도메인 지식과 회의 맥락을 누적하는 시스템으로 확장할 근거가 있다.

## 검토 결과
이 의견은 기존 설계와 잘 맞는다.

- N0028의 Thin Link 전략과 일치한다. `sync.jsonl`은 지식 저장소가 아니라 관련 엔트리로 향하는 얇은 포인터여야 한다는 방향을 강화한다.
- N0034의 SQLite Activity Index & AI Sessions와 일치한다. 세션 복원과 cold start 최적화가 실제 에이전트 사용성의 핵심이라는 외부 관찰 근거가 추가되었다.
- N0008의 `elf link` 설계와 연결된다. 본문 내 `see Nxxxx` 참조와 manifest `links`의 정합성 문제가 실사용 관점의 개선 포인트로 확인되었다.

## 승인된 개선 포인트
다음 세 항목을 후속 설계/구현 후보로 승인한다.

1. **Current Summary / Compiled Note**
   - 긴 revision chain을 매번 전부 읽지 않고도 최신 통합 상태를 빠르게 복원하는 파생 뷰가 필요하다.
   - source of truth는 기존 note + revisions로 유지하고, compiled view는 validate/rebuild 가능한 캐시 또는 명시적 생성물로 다룬다.

2. **Inline Reference와 Manifest Links의 정합성**
   - 본문 `see Nxxxx` 참조와 manifest `links` 사이의 불일치를 탐지하거나 보정하는 흐름이 필요하다.
   - `elf validate`의 경고 항목, 또는 `elf link sync` 같은 보조 명령 후보로 검토한다.

3. **sync_record 누락 방지 자동화**
   - 세션 종료/작업 완료 시 `sync_record` 누락은 장기 기억 계층의 신뢰도를 떨어뜨린다.
   - MCP 서버 또는 에이전트 프로토콜 차원에서 최소한의 종료 기록을 유도하는 자동화가 필요하다.

## 결정
이 피드백은 단순 감상이 아니라, elf MCP의 제품 방향을 뒷받침하는 승인 근거로 채택한다.

우선순위는 다음 순서가 타당하다.

1. current summary / compiled note 설계
2. `see Nxxxx`와 manifest links 정합성 검증
3. sync_record 자동화

이 순서는 세션 복원 품질을 먼저 높이고, 그 다음 링크 그래프의 신뢰도를 올린 뒤, 마지막으로 기록 누락 방지 자동화를 붙이는 흐름이다.
