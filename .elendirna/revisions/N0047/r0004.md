## Delta

## 구현 결정: `session_start` context injection 적용
`bundle --since`와 `depth` 사용 규칙을 별도 기능 추가 없이 MCP `session_start` active vault 응답에 주입하기로 결정하고 구현했다.

변경 내용:

- active vault 응답의 `next_action`을 `bundle(id)` 단일 경로에서 `bundle(id, depth/since)` 선택 유도로 수정했다.
- `context_hints.bundle_policy` 배열을 추가했다.
- 정책은 보수적으로 구성했다.
  - 처음 보거나 확실하지 않은 핵심 entry는 `bundle(id, depth=1)`.
  - 마지막 확인 revision을 알 때만 `bundle(id, depth=0, since='N####@r####')`.
  - 관련 후보 탐색은 `bundle(id, depth=2)` 후 필요한 entry만 다시 로드.
  - 긴 revision chain에서는 full bundle 전에 since 기준이 있는지 확인.

의도:

- compiled note 같은 새 저장 구조를 도입하기 전, 이미 존재하는 `depth`/`since` 기능을 에이전트가 세션 시작 시 자연스럽게 선택하도록 한다.
- `depth=0`과 `since`를 과도하게 유도하지 않도록 첫 규칙을 `depth=1` fallback으로 둔다.

검증:

- `cargo test` 통과: unit 40개, integration 5개, MCP integration 11개, sqlite integration 7개 모두 성공.
- 최초 sandbox 내 `cargo test`는 Windows target incremental 쓰기 access denied로 실패했으나, 권한 상승 재실행에서는 통과했다.
- `cargo fmt --check`는 저장소 전반의 기존 포맷 차이를 대량 보고하여 이번 변경 검증 신호로 사용하지 않았다.
