## 추가 관찰: MCP는 원격 서버라기보다 로컬 도구 프로토콜로 이해해야 함 (2026-04-30)

Discord 대화 추가분에서 ELF 원작자와 Elendirna 제작자 사이에 MCP 개념 오해가 정리되었다.

[Change]
- MCP의 "server"라는 표현은 반드시 원격 HTTP 서버를 뜻하지 않는다.
- 대표 transport는 HTTP와 stdio이며, Elendirna의 `elf serve --mcp`는 stdio 기반 로컬 실행에 가깝다.
- Elendirna MCP는 기존 CLI 명령어에 연결된 함수를 MCP tool surface로 래핑한 구조로 이해할 수 있다.
- 따라서 "터미널에서 쓰는 API" 또는 "로컬 도구 호출 프로토콜"이라는 설명이 ELF 사용자에게 더 직관적일 수 있다.

[Impact]
- ELF 사용자가 MCP를 자연어 기반 skill/프롬프트 규칙으로 오해할 수 있음이 드러났다.
- 제품 설명에서는 MCP를 "자연어 규칙을 매번 읽히는 방식"이 아니라 "JSON 기반 tool call + 짧은 자연어 안내를 가진 절차적 컨텍스트 주입"으로 설명하는 편이 정확하다.
- `LogConvention.md` 같은 자연어 로깅 규칙은 모델 내부 기억에 맡기는 대신, `write_structured_log(content)` 같은 도구/API로 외부화할 후보가 된다.
- 핵심 효율은 토큰 절감 자체보다, 모델이 매번 "규칙을 읽고 해석하고 적용"하는 사고 비용을 줄이고, 구조화된 입력 슬롯을 채우도록 강제하는 데 있다.

추가 제품 문장 후보:
- "MCP는 서버라기보다, AI가 로컬 CLI 기능을 표준화된 API처럼 호출하게 만드는 프로토콜이다."
- "규칙을 기억시키지 말고, 규칙이 적용되는 버튼을 제공한다."
- "자연어 컨벤션은 사람이 읽는 문서이고, MCP tool은 그 컨벤션의 실행 가능한 표면이다."
