## Delta

## 개발 운영 지침: public upstream / private workbench
Elendirna 개발 repo는 public canonical과 private workbench를 명시적으로 분리한다.

## Remote 역할

- `origin`: `https://github.com/elen-labs/elendirna-workbench.git`
  - private workbench repo.
  - raw `.elendirna` vault, sync log, exploratory notes, dogfooding 기록을 보존한다.
  - 기본 `git push` 대상이다.

- `upstream`: `https://github.com/elen-labs/elendirna.git`
  - public canonical repo.
  - 검토된 코드, 문서, fixture, release artifact만 포함한다.
  - public 반영 시에만 명시적으로 사용한다.

## Branch 정책

- `private-workbench`
  - private 전용 작업 브랜치.
  - raw `.elendirna`를 포함한다.
  - 기본 작업 및 vault 기록은 이 브랜치에서 수행한다.

- `main`
  - public-compatible tree.
  - `.elendirna`는 추적하지 않는다.
  - 공개 반영 대상이 될 수 있다.

## Public 반영 규칙

일상 작업에서는 `git push`가 private `origin`으로만 흐르게 둔다.

public canonical에 반영할 때는 반드시 의도적으로 다음 중 하나를 수행한다.

- clean branch에서 `git push upstream main`
- GitHub PR을 통해 `elen-labs/elendirna`로 선별 반영
- private vault insight를 docs/issue/patch로 승격한 뒤 반영

## 공개 제외 규칙

public repo와 crates package에는 다음을 포함하지 않는다.

- root `.elendirna/**`
- raw `sync.jsonl`
- private revision chain
- local graph/UI prototype 산출물: `elf_graph.html`, `elf_ui.py`, `graph_data.json`

현재 public repo의 일반 branch history에서는 위 항목을 제거했다. GitHub hidden PR refs 일부에는 과거 기록이 남아 있을 수 있으나, 당시 범위와 노출 위험을 고려해 수용 가능한 잔여물로 판단한다.

## 주의

`upstream` remote는 존재 자체를 잊지 말아야 하지만, 기본 push 대상으로 사용하지 않는다. public 반영은 항상 명시적인 승격 단계로 취급한다.
