## MCP = context injection 본질 (Discord 04-30 흡수, 2026-05-07)

Discord 04-30 (Pluvia/Eli) 토론에서 MCP의 본질에 대한 명시화. Non-Compulsive AI Guidance 원칙의 기술적 기반 보강.

### 핵심 명제

**MCP는 context injection 메커니즘이다.**
- system context보다 약함 (system prompt가 우선)
- 일반 대화 context보다 강함 (도구 응답이 자연어보다 권위 있음)
- tool 호출이 곧 "이 시점에 이 메모리/룰을 주입"의 명시 신호

→ AI가 룰을 기억할 필요가 없다. **도구 버튼만 누르면 메모리/룰이 등장한다.**

Pluvia 04-30: "MCP는 룰을 외화. AI가 기억하지 않아도 도구를 누르면 컨텍스트가 들어온다."
Eli 04-30: "compaction 후 모델 메모리에 의존하기보다 MCP/tool delegation으로 구조화 logging."

### 자연어 룰 vs tool description

per-query 50줄 logging convention을 매번 읽으면 cognitive load 큼. Tool description에 의도를 박으면 호출 시점에 자연스럽게 등장:
- 사용자/엔지니어가 룰을 한 번 정의 → tool description에 1~2줄
- AI는 호출 시 description으로 이미 룰 인지
- 도구 호출이 룰의 "재읽음"을 자연스럽게 트리거

### MCP body 형식 명세

Pluvia 04-30: "MCP body는 JSON-like + 짧은 자연어 가이드. context injection은 tool result 주변에서 일어남."

→ Elendirna의 모든 tool 응답은 (1) 구조화 JSON 데이터 + (2) tool description 기반 자연어 가이드가 결합되어 호출자에게 컨텍스트를 주입한다.

### Non-Compulsive 원칙과의 결합

기존 N0050 r0001~r0002에서 정한 "AI 강제 X, 자연 nudge"와 결합:
- tool description은 "압박"이 아니라 "맥락 잠재시키기"
- AI가 자기 판단으로 호출 → 결과 + description = 컨텍스트
- 강제 흐름 없이 자연스럽게 룰이 따라온다

[Change] MCP의 본질을 "context injection 메커니즘"으로 명문화. 자연어 룰 외화·tool description 활용 패턴 추가
[Impact] tool description 작성 표준이 명확해짐. 이후 신규 tool 도입 시 "1~2줄 자연어 가이드 + JSON 응답"으로 표준화 가능. Elendirna 외 generic MCP 디자인 reference 가능.
