## Delta

## 구현 점검 및 보완 방향 (2026-04-23)

N0051 시나리오를 현재 코드 기준으로 점검함.

### 구현되어 있는 것

1. CLI 전역 vault 선택 플래그
- `--vault <path>`와 `--global`은 `main.rs`의 global flag로 존재한다.
- 일반 CLI 명령은 `VaultArgs`를 통해 `resolve_vault_root`를 사용한다.
- `--vault > --global > ELF_VAULT > cwd 탐색 > global 폴백` 우선순위가 구현되어 있다.

2. MCP 응답의 vault 출처 표시
- `src/mcp/mod.rs`의 `vault_info()`가 응답에 `vault`, `vault_kind`를 붙인다.
- `entry_list`, `entry_show`, `entry_new`, `entry_status`, `revision_add`, `bundle`, `query`, `sync_record`, `validate`, `session_start` 응답에 출처가 포함된다.
- N0040의 “응답 출처 누락” 문제는 현재 코드상 해결되어 있다.

3. MCP 서버 시작 시 vault 선택
- `elf serve --mcp --vault <path>`로 특정 local vault를 primary vault로 시작할 수 있다.
- `ELF_VAULT`와 CWD 탐색도 동작한다.
- vault를 찾지 못하면 global vault를 생성/사용하는 현재 동작이 남아 있다.

### 아직 구현되지 않은 것

1. MCP tool 호출 단위 `vault` 파라미터
- `EntryListParams`, `EntryShowParams`, `EntryNewParams`, `RevisionAddParams`, `BundleParams`, `QueryParams`, `SyncRecordParams`, `ValidateParams`에 `vault: Option<String>`이 없다.
- 따라서 `query(vault='global', tag='refund-policy')` 같은 N0051의 핵심 흐름은 현재 불가능하다.

2. 세션 단위 local 등록
- `ElfMcpServer`에는 `local_vault: Option<PathBuf>` 필드가 없다.
- `session_start(local_vault=..., confirm=...)` 파라미터도 없다.
- 따라서 Desktop처럼 global primary로 뜬 서버가 대화 중 특정 repo local vault를 등록하는 흐름은 아직 구현되지 않았다.

3. `resolve_tool_vault` 공통 함수
- N0039에서 제안한 `resolve_tool_vault(explicit, local, primary)`가 없다.
- 현재 모든 MCP tool은 `self.vault_root` 하나만 사용한다.

4. `vault_kind` 판별 정확도
- 현재 `vault_info()`는 `self.vault_root == home`이면 global로 본다.
- normalize된 vault root가 home directory인 현재 모델에서는 대체로 맞지만, 장기적으로는 `home_vault_root()` 또는 metadata root 기준 판별 helper로 통일하는 편이 안전하다.

### 시나리오 관점 현재 지원 수준

- local repo에서 MCP 서버를 `--vault <repo>`로 시작하고 local vault만 쓰는 흐름: 가능
- global vault만 보려면 서버를 `--global` 또는 home/global로 별도 시작: 가능
- 같은 MCP 세션 안에서 local 구현 맥락과 global 업무 규칙을 번갈아 조회: 아직 불가능
- 조회 출처를 응답에서 확인하는 것: 가능
- global 오염 방지를 위한 write boundary: 정책은 정리되어 있으나 코드 레벨 guard는 아직 없음

### 보완 우선순위

1. MCP params에 `vault: Option<String>` 추가
읽기 tool부터 적용: `entry_list`, `entry_show`, `bundle`, `query`, `validate`.
이 단계만으로도 N0051의 “local 작업 중 global 업무 규칙 참조”는 상당 부분 가능해진다.

2. `resolve_tool_vault` 도입
해석 순서:
- explicit `global` → home vault
- explicit `local` → session local vault, 없으면 에러
- explicit absolute path → normalize 후 사용
- explicit alias → global config alias 조회
- explicit 없음 + local 등록됨 → local
- explicit 없음 → primary

3. 쓰기 tool에 `vault` 적용하되 guard 추가
`entry_new`, `revision_add`, `entry_status`, `sync_record`에도 vault override를 허용할 수 있지만, `vault='global'` 쓰기는 응답/설명 차원에서 더 강한 경고 또는 별도 confirm 설계가 필요하다.
N0051 관점에서는 기본 쓰기 대상이 local이어야 한다.

4. `session_start(local_vault, confirm)` 구현
Desktop/Claude Code류 환경에서 primary vault와 repo local vault가 어긋나는 문제를 해결한다.
프로세스 인메모리 등록으로 config.toml 오염을 피한다.

5. 테스트 추가
- primary local에서 `query(vault='global')`이 global entry만 반환하는 테스트
- primary global + session_start(local_vault=repo) 후 기본 query가 local을 보는 테스트
- `revision_add` 기본 쓰기가 local로 가는 테스트
- global write override가 명시적으로만 동작하는 테스트

### 결론

N0051은 제품 시나리오로는 좋고, 현재 구현은 그 전단계에 있다.
출처 표시와 서버 시작 시 vault 선택은 구현되어 있지만, 핵심인 “동일 MCP 세션에서 local/global을 tool 호출 단위로 분리 조회”는 아직 미구현이다.
