## Delta

## 현재 구현의 격리 특성 재평가 (2026-04-24)

Codex Desktop 환경에서 현재 MCP 작동을 확인한 결과, `ElfMcpServer`가 시작 시점의 `vault_root` 하나만 보유하고 모든 tool 호출이 `self.vault_root`만 참조한다는 점을 재확인함.

따라서 같은 MCP 세션 안에서 local/global이 호출 단위로 섞여 읽히거나 쓰이는 자료 혼합/유출 위험은 현재 구조상 낮다. 오히려 현재의 주요 리스크는 multi-vault 혼합이 아니라, 서버 시작 시점에 사용자가 기대한 vault가 아닌 다른 primary vault로 고정되는 경우다.

응답에 `vault`, `vault_kind`가 포함되어 있으므로 에이전트는 세션 시작과 주요 작업 전 출처를 확인해야 한다. multi-vault override가 구현되기 전까지는 격리성은 강하지만 참조 유연성은 낮은 상태로 보는 것이 정확하다.
