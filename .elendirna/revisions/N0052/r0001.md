# PLAN v0.5 — Local-first MCP 완성도와 첨부파일 MVP

> 전제: v0.4 완료 후 다음 버전 후보 정리
> 관련: → see N0039, N0038, N0051, N0021, N0041, N0046, N0050

## 테마

v0.5의 테마는 "stdio MCP의 local-first 현실을 받아들이고, CLI와 MCP가 같은 코어 기능을 안정적으로 공유하게 만드는 것"이다.

HTTP/SSE 또는 원격 파일 업로드보다, 현재 실사용성이 높은 stdio MCP + 로컬 파일시스템 모델을 우선한다.

## 확정 스코프

### 1. MCP multi-vault 완성 [x]

목표: 같은 MCP 세션 안에서 local/global/alias vault를 명시적으로 읽고, 쓰기 경계를 안전하게 유지한다.

구현 항목:
- MCP tool params에 `vault: Option<String>` 추가
  - read: `entry_list`, `entry_show`, `bundle`, `query`, `validate`
  - write: `entry_new`, `revision_add`, `entry_status`, `sync_record`
- `resolve_tool_vault(explicit, session_local, primary)` 공통 함수 도입
- `session_start(local_vault: Option<String>, confirm: Option<bool>)` 지원
- `local`, `global` 예약어 확정
- 응답에 `vault`, `vault_kind`, 가능하면 `vault_resolution` 포함
- fallback global 사용 시 `fallback: true` + `warning` 동시 반환
- explicit global/external write에는 `confirm=true` 요구 검토/적용

성공 기준:
- primary local 세션에서 `query(vault='global')`로 global vault를 조회할 수 있다.
- primary global 세션에서도 `session_start(local_vault=...)` 후 기본 호출이 session local을 우선한다.
- 모든 MCP 응답에서 실제 resolved vault를 확인할 수 있다.
- 명시 접근 실패 시 다른 vault로 자동 fallback하지 않는다.

### 2. 첨부파일 CLI/MCP MVP [x]

목표: 파일 내용을 MCP stdio로 직접 전송하기보다, CLI와 MCP가 같은 local path import 모델을 공유한다.

판단:
- stdio MCP는 JSON-RPC over stdin/stdout이며 별도 binary stream이 없다.
- base64 blob 전송은 가능하지만 대용량/재시도/청크/메모리 문제가 커서 MVP에 부적합하다.
- 따라서 다음 버전은 local path 기반 attach/detach/assets로 시작한다.

구현 항목:
- CLI
  - `elf entry attach <ID> <FILE_PATH> [--label <TEXT>] [--copy-name <NAME>] [--json]`
  - `elf entry detach <ID> <ASSET_KEY> [--json]`
  - `elf entry assets <ID> [--json]`
- MCP
  - `entry_attach(id, path, label?, copy_name?, vault?)`
  - `entry_detach(id, asset_key, vault?)`
  - `entry_assets(id, vault?)`
- 파일은 `.elendirna/assets/`로 복사
- `manifest.sources`에 asset key 추가/삭제
- sync 이벤트 기록: `entry.attach`, `entry.detach`
- 응답 메타데이터 포함
  - resolved vault
  - source path
  - copied asset key
  - size
  - mime 가능 시
  - 상대 경로였을 경우 어떤 cwd 기준으로 해석했는지

성공 기준:
- attach 후 `entry show --json` 또는 MCP `entry_show`에서 sources에 key가 보인다.
- detach 후 sources에서 key가 제거된다.
- 다른 entry가 참조하지 않는 asset은 정리된다.
- validate가 assets/sources dangling 또는 미등록 상태를 올바르게 감지한다.
- CLI와 MCP가 동일 코어 함수를 공유한다.

### 3. MCP sync_record entries 역직렬화 수정 [ ]

목표: MCP `sync_record(entries=[...])` 호출이 정상 동작하게 한다.

문제:
- `entries` 배열이 문자열화되어 들어오거나 schema/역직렬화 계층에서 `Vec<String>`으로 처리되지 않는 오류가 있었다.
- 이는 핵심 지식 모델 손상이 아니라, 선택적 handoff 힌트 API의 품질 문제다.

구현 항목:
- `SyncRecordParams.entries` schema 확인
- rmcp 배열 파라미터 역직렬화 방식 확인
- 필요 시 관대한 deserializer 도입
  - `Vec<String>`
  - comma-separated string
  - stringified JSON array
- 테스트 추가

성공 기준:
- MCP에서 `entries: ["N0021", "N0041"]` 입력이 성공한다.
- 기존 CLI `--entries "N0021,N0041"` 경로도 유지된다.

## 논의 보류

### 4. Single-step Undo [?]

상태: 다음 버전 확정 구현이 아니라 추가 논의 대상.

논의 필요:
- hard delete vs soft delete
- 전역 최신 write 1건 기준 vs entry별 최신 revision 기준
- `sync.jsonl` undo 기록 방식
- `entry_new` undo 허용 조건
- 불변 revision history 원칙과의 충돌 범위

잠정 판단:
- UX 가치는 크지만, Elendirna의 계보/불변성 철학과 직접 연결되므로 구현 전에 정책 확정이 필요하다.

## 명시적 비범위

v0.5에서는 다음을 구현하지 않는다.

- HTTP/Streamable upload session
- chunk upload
- resume/retry
- remote object storage
- SSE transport
- 첨부파일 CAS dedup
- 첨부파일 sha256/full validate
- 구조화 `[[sources]]` migration
- publish draft workflow
- collaborative identity/bot support

## 구현 순서 권장

1. MCP multi-vault read path부터 구현
2. `session_start(local_vault, confirm)` 및 `resolve_tool_vault` 공통화
3. write tool vault override + confirm 정책 적용
4. CLI 첨부파일 attach/detach/assets 구현
5. MCP 첨부파일 tool을 CLI와 같은 core op에 연결
6. sync_record entries 역직렬화 수정
7. 전체 테스트 및 MCP integration test 보강

## 결론

v0.5는 화려한 원격 기능보다 현재 stdio MCP와 CLI가 실제로 공유하는 local-first 실행 모델을 단단하게 만드는 버전이다. multi-vault는 읽기/쓰기 경계의 안전성을 높이고, 첨부파일 MVP는 텍스트 밖의 증거 자료를 vault에 안정적으로 연결한다. sync_record 수정은 작은 API 품질 보강으로 함께 처리한다.
