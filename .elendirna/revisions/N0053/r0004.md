## Delta

## 변형 모델: Gemini를 중재자/진행자로 두고 Codex와 Claude Code에 질문·작업 지시 (2026-04-24)

사용자 제안:
Gemini에게 중재자 역할을 맡기고, Gemini가 Codex와 Claude Code(CC) 양쪽에 일을 시키거나 질문하는 구조도 가능하다.

### 구조

- Gemini: 중재자/진행자 agent. 쟁점을 정리하고, Codex/CC에게 질문하거나 작업을 분배한다.
- Codex / Claude Code: 전문 참여자 agent. 구현 검토, 코드 수정, 설계 반박, 테스트 확인 등 구체적 과제를 수행한다.
- 사람: 최종 sponsor/owner. 중재 진행을 관찰하고, canonical 승격 또는 중요한 방향 전환을 승인한다.
- `elf`: shared memory. 쟁점, 지시, agent 응답, 승격된 결론을 기록한다.

### N0053 사회자 모델과의 차이

기존 모델에서는 사람이 직접 사회자였다. 이 변형에서는 사회자 기능의 일부를 Gemini에게 위임한다. 사람은 모든 발언을 직접 조율하지 않고, Gemini가 만든 agenda와 질문 흐름을 검토하는 상위 감독자 역할에 가까워진다.

즉 역할은 다음처럼 계층화된다.

- 사람: final authority / escalation gate
- Gemini: moderator / task router / synthesis agent
- Codex, CC: discussants / workers / reviewers
- elf: durable memory and audit trail

### 장점

- 사람이 모든 질문을 설계하지 않아도 된다.
- Gemini가 Codex와 CC의 의견 차이를 정리하고 추가 질문을 던질 수 있다.
- Codex는 코드/구현 검토, CC는 다른 관점의 설계/리뷰 등으로 역할을 분화할 수 있다.
- 중재자가 agenda를 유지하면 live chat이 산만해지는 것을 줄일 수 있다.

### 리스크

- 중재자 agent가 의제를 잘못 잡으면 토론 전체가 한쪽으로 기울 수 있다.
- Gemini가 Codex/CC의 의견을 과도하게 요약하거나 누락할 수 있다.
- 사람이 canonical 승격 gate를 놓치면 agent 간 합의가 곧 결정처럼 보일 수 있다.
- 중재자도 agent이므로 echo chamber drift를 완전히 막지 못한다.

### 운영 원칙 후보

- Gemini는 `propose agenda`, `ask`, `summarize contested points`까지 맡는다.
- canonical `revision_add` 또는 stable decision 승격은 사람 승인 후 수행한다.
- Gemini의 요약은 원 발언/근거 entry/revision refs를 반드시 포함해야 한다.
- Codex/CC의 원 응답은 가능한 한 `sync_record` 또는 draft discussion record로 추적 가능해야 한다.
- Gemini가 내린 결론은 "decision"이 아니라 "moderator recommendation"으로 표시한다.

### 프로토콜 함의

agent-discussion protocol에는 사람 사회자 모델뿐 아니라 delegated moderator 모델도 포함해야 한다. 따라서 `author`만으로는 부족하고, 발언의 역할(role)을 구분해야 한다.

필요한 role 후보:
- `moderator`
- `participant`
- `reviewer`
- `worker`
- `synthesizer`
- `human-owner`

또한 중재자가 생성한 요약/질문/권고가 원 참여자 발언과 구분되어야 한다.
