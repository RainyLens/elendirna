## Delta

# Instruction: Phase 1 - MCP Multi-vault Completion

본 지시는 v0.5 마일스톤의 첫 번째 단계인 'MCP 멀티 볼트 지원 완성'을 목표로 합니다.

## 배경
현재 MCP 서버는 기동 시 지정된 `vault_root` 하나만 고정해서 사용합니다. v0.5에서는 하나의 MCP 세션 내에서 `vault` 파라미터를 통해 `local`, `global` 또는 특정 별칭(`alias`) 볼트에 동적으로 접근할 수 있어야 합니다.

## 요구사항

### 1. `ElfMcpServer` 구조체 수정 (`src/mcp/mod.rs`)
- `session_local_vault: std::sync::RwLock<Option<PathBuf>>` 필드를 추가하십시오.
- `session_start` 도구 호출 시 이 필드를 업데이트하여 해당 세션의 기본 볼트를 변경할 수 있게 합니다.

### 2. 볼트 해결 로직 구현
- `resolve_tool_vault(&self, explicit_vault: Option<String>) -> Result<PathBuf, ErrorData>` 메서드를 구현하십시오.
- **우선순위:** 명시적 파라미터(`vault`) > 세션 로컬 볼트 > 서버 기본 볼트(`vault_root`)
- `local`, `global` 예약어를 처리해야 하며, `src/vault/mod.rs`의 `resolve_vault_alias`를 활용하십시오.

### 3. 모든 MCP 도구 파라미터 업데이트
- 다음 구조체들에 `vault: Option<String>` 필드를 추가하십시오:
    - `EntryListParams`, `EntryShowParams`, `EntryNewParams`, `EntryStatusParams`, `RevisionAddParams`, `BundleParams`, `QueryParams`, `SyncRecordParams`, `ValidateParams`
- 각 도구 구현부에서 `resolve_tool_vault`를 호출하여 실제 작업 대상 경로를 결정하십시오.

### 4. 응답 메타데이터 보강
- 모든 도구의 성공 응답(JSON)에 다음 필드를 포함하십시오:
    - `vault`: 실제 작업이 수행된 볼트의 절대 경로
    - `vault_kind`: "local" 또는 "global"

## 주의사항
- `src/vault/ops.rs`의 코어 로직은 이미 볼트 경로를 인자로 받으므로, MCP 레이어에서의 경로 결정 로직에 집중하십시오.
- 코드 수정 후 `cargo check`를 통해 타입 안정성을 확인하십시오.
- 작업 완료 후 N0052(PLAN v0.5)의 체크리스트를 업데이트하십시오.
