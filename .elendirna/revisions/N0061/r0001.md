## CLI별 Non-Interactive / YOLO 모드 비교 (2026-04-27)

### 공통 전제
- 세 도구 모두 CLI 호출 수준에서 권한 프롬프트 없는 완전 자동 실행 가능
- subprocess / 파이프 입력 모두 지원
- CWD 기반 vault 해석: 호출 디렉터리가 vault 경로 결정에 영향

### Claude Code
- YOLO 플래그: `--dangerously-skip-permissions`
- 비대화형: `-p "prompt"`
- config 고정: `settings.json` → `permissions.defaultMode`
- 도구 제한: `--allowedTools "mcp__localvault__*,Bash(elf *)"`
- 빠른 시작: `--bare` (MCP/hook 자동탐색 스킵)

```bash
claude -p "task" --dangerously-skip-permissions --bare \
  --allowedTools "mcp__localvault__*,Bash(elf *)"
```

### Gemini CLI
- YOLO 플래그: `--yolo` (또는 `--approval-mode yolo`)
- 비대화형: positional prompt (또는 deprecated `-p`)
- config 고정: **불가** — `settings.json`에서 `yolo` 값 허용 안 함 (flag only)
- MCP 신뢰: `mcpServers.<name>.trust = true`로 서버 단위 pre-authorize
- 폴더 신뢰: `GEMINI_CLI_TRUST_WORKSPACE=true` 환경변수

```bash
GEMINI_CLI_TRUST_WORKSPACE=true gemini --yolo "task"
```

### Codex CLI
- YOLO 플래그: `codex exec --dangerously-bypass-approvals-and-sandbox`
  - (주의: `--approval-policy never` 는 실제 존재하지 않음 — 잘못된 정보)
- 비대화형: `codex exec "prompt"` (subcommand 필요)
- config 고정: `~/.codex/config.toml` → 각 tool별 `approval_mode = "allow"` 또는 전역 설정
- 현재 config 상태: tool별 `approval_mode = "approve"` → 플래그로 override 필요

```bash
codex exec --dangerously-bypass-approvals-and-sandbox "task"
```
