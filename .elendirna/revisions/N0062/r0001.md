### 확인된 이슈

1. `"local"` alias 의미 불일치
   - `resolve_named_vault("local")` → `vault_root` 반환 (설계는 session_local_vault)
   - `vault=None` vs `vault="local"` 동작 불일치

2. `vault_resolution` 필드 누락
   - 응답에 vault/vault_kind만 있고 선택 경위 없음
   - "의도적 global"과 "fallback global" 구분 불가

3. FallbackGlobal 경고 누락
   - 암묵적 global fallback 시 fallback:true + warning 미반환

4. Write confirm 미구현
   - global/external 대상 write tool에 confirm 없음

### 구현 계획 (Codex 검토 반영 수정)

**Phase 1 — VaultProvenance 구조 정의**
- `VaultProvenance` enum: ExplicitPath / ExplicitGlobal / EnvVar / CwdSearch / GlobalFallback
- `ElfMcpServer::new(vault_root: PathBuf, provenance: VaultProvenance)` signature 변경
- `serve.rs` 에서 provenance 결정 후 전달 (mod.rs만 변경으로는 해결 불가)

**Phase 2 — Resolver 리팩터 + "local" 의미 확정**
- `VaultResolution` enum 세분화:
  ExplicitGlobal / ExplicitLocal / ExplicitAlias / ExplicitPath / SessionLocal / ServerDefault / FallbackGlobal
- `resolve_tool_vault` 반환 타입: `(PathBuf, VaultResolution)`
- `"local"` = session_local_vault 등록 시 그 경로, 미등록 시 에러
- 관련 테스트 semantics 변경 필요 (구동 이슈 아닌 의미 변경)

**Phase 3 — 응답 메타데이터**
- 모든 tool 응답에 `vault_resolution` 필드 추가
- FallbackGlobal 시 `fallback: true` + `warning` 동시 반환

**Phase 4 — Write guard (v0.5.1: warning-only)**
- 적용 tool: entry_new, revision_add, sync_record, entry_status, entry_attach, entry_detach
- `#[serde(default)] confirm: bool` — 역호환
- v0.5.1: confirm 없이 global/external write 시 warning만
- block은 v0.6에서
