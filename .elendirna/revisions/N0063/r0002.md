## Delta

## 아이디어: 검토 결과 불만족 시 loop 반복 (2026-04-27)

[Change] 협업 흐름에 반복 루프 옵션 추가.

기본 흐름(Gemini → Codex → Claude)에서 Codex 검토 결과가 불충분하거나 Gemini 제안이 너무 얕을 경우, Claude가 최종 종합 전에 루프를 몇 회 더 돌 수 있다.

### 반복 조건 판단 기준 (Claude 기준)
- Codex가 제안의 근본 구조를 부정했을 때 (단순 지적이 아니라 방향 자체가 틀림)
- Gemini 재제안이 필요할 정도로 첫 초안이 컨텍스트를 충분히 반영 못했을 때
- 사용자가 명시적으로 "한 번 더 돌려봐" 요청 시

### 루프 구조 예시

```
Round 1: Gemini(초안) → Codex(검토)
  └─ 불만족 시
Round 2: Gemini(보완 제안, Codex 피드백 반영) → Codex(재검토)
  └─ 불만족 시
Round 3: ...
  └─ 만족 또는 max round 도달
Claude: 최종 종합
```

### 실용적 제한
- 기본 max round: 2~3회 (컨텍스트/비용 고려)
- 루프마다 이전 round 결과를 프롬프트에 누적해서 전달
- Claude가 루프 종료 판단: "Codex가 이전과 같은 지적을 반복하면 수렴한 것으로 간주"

[Impact] 단순 1회 협업보다 복잡한 이슈에서 품질 향상 기대. 특히 설계 검토처럼 반례가 많은 작업에 유효.
