## 작업 유형별 모델 분담 가이드 (2026-05-07)

지금까지의 협업 패턴을 명시 운영 룰로 고정.

### 분담
- **코드 작업, 작업 계획 검증** → **codex** (consistency / static analysis)
- **새 아이디어 검토, 발산적 brainstorm** → **gemini** (ideation / curation)
- 코드 생성과 통합은 Claude — 외부 모델은 검증/발산 두 트랙으로만 호출

### 호출 전 3종 점검 (체크리스트)
1. **CLI 권한 모드**
   - codex: `exec --dangerously-bypass-approvals-and-sandbox` (또는 등가 YOLO)
   - gemini: `-p "..." --yolo` 또는 `--approval-mode yolo`
   - 권한 누락 시 sub-agent가 read-only로 멈춰 산출물 부재
2. **MCP 상태**
   - `codex mcp list` / `gemini mcp list`로 elendirna MCP가 붙어 있는지 확인
   - 미연결이면 prompt에 vault entry 본문을 직접 inline 전달
3. **vault 공유 유도**
   - vault path/alias/필요한 entry ID를 prompt에 명시
   - 가능하면 bundle(id) 결과를 직접 prompt에 포함 (cross-validation 흔적 필요 시)

### 결과 통합 규칙
외부 모델 응답은 vault entry에 cross-validation 흔적으로 기록.
패턴: N0065 r0002 (codex/gemini 종합), N0038 r0014 (codex/gemini 검증), N0068 r0001 (codex 독립 재현).

### 안티패턴
- 권한 모드 확인 없이 호출 → 빈 응답
- vault 컨텍스트 미전달 → 일반론 응답, 종합 가치 낮음
- 한 모델로 코드+아이디어 모두 처리 → 발산/수렴 분리 손해
