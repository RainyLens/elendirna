- CC Desktop이 process cwd=home에서 MCP 서버 기동 → launch_resolution이 사용자 의도와 어긋남

### codex 추가 발견: 가드는 이미 부분 구현, 다만 **CwdSearch origin이 함정**

main 브랜치(현재) 코드에 이미 들어온 보강:
- `vault_meta`: `vault`, `vault_kind`, `vault_origin`, `fallback`, `warning` 응답에 노출
- 모든 write tool에 `VaultOrigin::FallbackGlobal && !p.confirm` 시 reject (entry_new/revision_add/sync_record 등 7곳)
- session_start hint에 "글로벌 vault 활성화" 안내

그런데 **함정**:
- `src/cli/serve.rs:37`에서 `find_vault_root` 성공 시 origin = `CwdSearch` (FallbackGlobal 아님)
- CC Desktop의 process cwd=home인데 home에 `.elendirna/config.toml`이 init되어 있으면 → cwd 탐색 첫 hit가 home → origin = **CwdSearch** (not FallbackGlobal)
- 따라서 fallback confirm 가드가 **트리거 안 됨**
- 사용자가 `entry_new(vault='local')` → launch_resolution(path=home, origin=CwdSearch) → confirm 없이 글로벌에 silent write 가능

→ N0067 보고된 silent global write의 **구체적 인과**: cwd 탐색이 home의 글로벌 vault에 첫 매칭 → CwdSearch origin → fallback 가드 우회

### 보강 fix 후보 (codex 분석 + 통합)

A. **CwdSearch가 home/.elendirna에 매칭된 경우를 별 origin으로 분리**
   - 새 origin: `CwdSearchHome` 또는 `HomeMatchedAsLocal`
   - write 가드를 FallbackGlobal + CwdSearchHome 둘 다 적용
   - 가장 작은 변경 단위

B. **'local' 별칭의 시맨틱을 재정의**
   - "process cwd부터 탐색하되 home에 닿기 전에 멈춤" 또는 "session_start에서 명시 등록된 path만 'local'"
   - N0038 sudo 정책과 정합. 더 큰 변경

C. **session_start(local_path=...) 명시 등록 인터페이스** (앞 r0002의 옵션 2)
   - cognitive load 있지만 명확. CC Desktop 사용자에게 권고
   - B와 결합 가능

### N0038 sudo 정책에 미치는 영향
