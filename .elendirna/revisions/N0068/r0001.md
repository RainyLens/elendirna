## 발생 (2026-04-30)

ubuntu-latest CI에서 mcp::tests::resolve_local_uses_server_vault_not_process_cwd 가 v0.5.0 release 이후 간헐적으로 fail. 5번 연속 fail 누적.

```
panicked at src/mcp/mod.rs:995:47:
called `Result::unwrap()` on an `Err` value:
  Os { code: 2, kind: NotFound, message: "No such file or directory" }
```

## 진단

- src/lib.rs:11에 `pub(crate) static CWD_LOCK`이 정의되어 있고 cli/tests.rs와 schema/tests.rs는 모두 `crate::CWD_LOCK`으로 set_current_dir 직렬화.
- 그러나 src/mcp/mod.rs:976에 **별도의 로컬 `static CWD_LOCK`**이 또 정의되어 있고 mcp 테스트만 이걸 사용. **두 lock이 분리되어 cli/schema 테스트와 mcp 테스트가 직렬화되지 않음.**

scenario:
1. cli 테스트가 lib lock 잡고 set_current_dir(tempdir) 후 함수 종료. tempdir drop으로 디렉토리 즉시 삭제 (Linux). lock release. CWD = deleted dir.
2. mcp 테스트가 자기 로컬 lock 잡고 시작 → current_dir() → NotFound panic.

Windows는 디렉토리 핸들 잡혀 있을 때 즉시 삭제 안 되므로 로컬 통과 (typical Windows-passes-Linux-fails race).

부수: 사용자가 GitHub web에서 만든 upstream 1eaa078 "Run tests for library only in CI workflow" (--lib 추가)는 lib 안에서 fail하는 race를 우회 못 해 효과 없었음.

## Fix (commit 8b538a6 = upstream / 054856f = workbench)

1. mcp 모듈 로컬 CWD_LOCK 제거 → `crate::CWD_LOCK` 사용 (lib level 단일 lock으로 통합)
2. current_dir() save/restore 폐기 → `env!("CARGO_MANIFEST_DIR")`로 cleanup. 이전 cwd save 자체가 race 위험 (저장 시점에 valid한 path가 복원 시점에 사라진 tempdir일 수 있음).

테스트 검증 의미는 그대로 (`assert_eq!(resolved.path, canonical(local.path()))`). cleanup 메커니즘만 race-safe로 정비.

## codex 상호검증

codex가 같은 panic을 독립 재현하고 같은 `CARGO_MANIFEST_DIR` 해법 독립 제안. 내 1차 fix(`current_dir().unwrap_or_else(temp_dir)`)는 line 995 panic은 막았으나 line 1008 cleanup에서 동일 race가 또 발생한다는 것을 codex가 cargo test로 재현해서 짚어줌. → CARGO_MANIFEST_DIR 안으로 바꿔서 해결.
