## Delta

## Goal

bundle 응답에 `sync_history`(해당 entry가 등장한 sync_record 시간 역순 요약)를 자동 포함하여, sub-agent가 entry 컨텍스트를 가져올 때 "이 entry가 살아온 이력"을 함께 본다. 새 데이터 모델 없이 read-path만 확장.

baseline: N0065 (Idea: work_context = sync_record entry-axis view). 분기 (a) 채택 (N0065 r0003).

## Scope

### IN
- `bundle(id)` 응답에 `sync_history` 필드 추가
  - 형태: `[{ts, agent, summary, sync_id}]` (요약형, **co_entries 미포함**)
  - 정렬: ts 역순
  - limit: 5~10 (정확한 숫자는 구현 시 결정)
  - 자동 포함 (option flag 없이)
- AGENTS.md / Claude.md / tool description 짧은 설명 추가
- sync_record.entries 의미 docs 박기: "touched in this session"
- 테스트: 빈/다중/누락 entry/삭제된 entry 케이스

### OUT (v0.5.3+ 트랙)
- `co_entries` (sibling 힌트) — 빈도/최근성 가중, loop 가드, AGENTS.md 가이드 동반 필요
- sqlite SSoT 뒤집기 (jsonl ↔ sqlite reconcile)
- `session_start`의 working_tree nudge wording 개선
- `bundle` 옵션 flag (`include_sync_history=false`) — 부담스러우면 v0.5.3 추가

## 구현 단계

1. **schema/index**: `index.sqlite`에 sync_history 조회용 query 또는 in-memory cache (validate 시 rebuild)
2. **vault/ops/bundle**: `bundle()` 함수에 sync_history 채우기. limit/sort 적용
3. **mcp/mod.rs `bundle` tool**: 응답 JSON에 `sync_history` 필드 포함
4. **schema/validate**: sync_history rebuild 검증 (drift 감지)
5. **docs**: AGENTS.md, tool description 갱신
6. **tests**: 단위 + integration

## API 모양

기존 bundle 응답:
```json
{
  "manifest": {...},
  "note": "...",
  "revisions": [...],
  "linked": [...],
  "sync_history": [   // ← 신규
    {"ts": "...", "agent": "claude", "summary": "...", "sync_id": "..."},
    ...
  ]
}
```

## 리스크/판단

- **invalid entry id**: sync_record가 미존재 ID 참조 시 sync_history는 dead link 무시 (codex 권고 r0002 backward compat)
- **deleted/merged entry**: graceful degradation. sync_history는 sync.jsonl 기준이라 entry가 사라져도 jsonl 행은 남음 → 다른 entry의 sync_history엔 그 sync_id가 그대로 노출. 본 PLAN에서는 정상 동작 (jsonl이 SSoT)
- **bundle 응답 크기**: limit 5~10이면 entry당 추가 ~1KB 미만. 무시 가능
- **agent loop**: co_entries 미포함이므로 hop loop 위험 없음 — v0.5.3 작업에서 다룸

## 성공 기준

- bundle 응답에 sync_history 자동 포함, 시간 역순, limit 충족
