## codex 사전 검증 결과 (2026-05-11, Phase A 시작 전, Claude+codex 협업)

elendirna MCP를 codex가 직접 사용해 N0070/N0067/N0038을 흡수, Phase A 변경 의도를 design 단계에서 review. 본 PLAN의 한 가지 결함 + 두 권고 발견.

### High — Phase A 3(b) 제거

`resolve_vault_alias(alias: &str) -> Option<PathBuf>` signature는 origin 정보를 carry 못 함. PLAN r0001/r0002에서 보강한 "alias 'local' 진입점도 wrap" 항목은 signature 변경 없이는 구현 불가.

하지만 codex가 동시에 발견: MCP의 explicit `vault="local"` 호출은 [src/mcp/mod.rs:106](src/mcp/mod.rs)에서 `launch_resolution.origin`을 그대로 복사한다. 즉 alias 경로의 silent global write는 사실 발생하지 않음 — `launch_resolution`이 이미 origin을 정확히 carry.

**결론: wrap은 serve.rs launch resolution 한 곳에서만 충분.** 두 진입점 접근 폐기.

### Medium — `is_home_vault_root(&Path) -> bool` helper 추출

home 비교 로직이 [src/cli/serve.rs:39-50](src/cli/serve.rs), [src/mcp/mod.rs:60-66](src/mcp/mod.rs) `vault_meta`, [src/vault/mod.rs:76-83](src/vault/mod.rs) `home_vault_root`에 흩뿌려져 있음. Windows USERPROFILE/HOME, junction, trailing slash, `\\?\` canonical path 차이를 단일 helper로 흡수. 양쪽 모두 canonicalize → 비교, 둘 중 하나 fail 시 보수적 false (기존 `CwdSearch` 유지, 안전 degrade).

### Medium — 응답 계약 테스트

enum variant 추가 시 compile은 잡혀도 serde/응답 string 누락은 못 잡음. CwdSearchHome state 하에서 `vault_kind="global"` + `vault_origin="cwd_search_home"` 조합을 고정하는 integration test 필요.

### Low — variant 순서

[src/vault/mod.rs:17](src/vault/mod.rs) `CwdSearch` 바로 뒤에 `CwdSearchHome`이 가장 읽기 좋음.
