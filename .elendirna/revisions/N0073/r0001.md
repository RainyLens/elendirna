## Delta

## [Change] systemic 진단 — MCP 클라이언트 typed param stringify

### 증상

2026-05-07 N0072 생성 세션에서 N0041과 같은 결의 deserialize 오류가 *다른 tool*에서 재발견됨. N0041 fix(r0006 FlexibleEntries)는 `sync_record.entries`에만 적용된 국소 처방이었고, 같은 루트가 다른 파라미터에서 그대로 발현 중.

확인된 affected sites (모두 같은 세션):

1. **`entry_new.tags`** (`Vec<String>`)
   ```
   3가지 형식 모두 실패:
   - JSON-stringified array literal: ["philosophy","roadmap",...]
   - comma-separated string: "philosophy, roadmap, ..."
   - bare JSON array
   에러: failed to deserialize parameters: invalid type: string "[...]", expected a sequence
   ```

2. **`bundle.depth`** (`u32`)
   ```
   에러: failed to deserialize parameters: invalid type: string "0", expected u32
   ```

3. (이전 세션) **`sync_record.entries`** — N0041 r0006에서 FlexibleEntries로 수용

### 진단

MCP 클라이언트(claude-code 측)가 **모든 typed param을 string으로 stringify**하여 보내고 있음. string 타입 param(`title`, `delta`, `id`, `summary`)은 영향 없음 — 본 세션 내 모든 string param은 정상 동작. 비-string param(array, integer)이 일률적으로 실패.

따라서 N0041의 *"FlexibleEntries로 entries만 수용"* 패치는 **국소 우회**였고, 진짜 루트는:
- (a) MCP 클라이언트가 타입 정보를 무시하고 stringify하는 것, 또는
- (b) 서버 측 스키마가 클라이언트가 인식할 수 있는 형식으로 선언되지 않은 것

### 영향 범위

현재 영향 받는 것으로 추정되는 tool 파라미터:
- `entry_new.tags: Vec<String>`
- `bundle.depth: u32`
- `bundle.since` (string이라 영향 없음)
- `query` 의 다양한 필터 (string은 OK, 혹시 typed가 있다면 영향)
- `entry_list.status`, `entry_list.tag` (string이면 OK)

검증 필요한 tool — 모든 비-string param.

### N0041 대비 추가 사항

N0041은 *"sync_record는 보조 힌트라 느슨하게 수용"* 결로 해결됐지만, `entry_new.tags`나 `bundle.depth`는 보조 힌트가 아니라 **core 데이터 모델 입력**임. 따라서:
- N0041의 *"느슨한 수용으로 우회"* 전략은 그대로 적용 안 됨
- 루트(MCP 클라이언트 stringify) 자체를 고치거나, 모든 typed param에 FlexibleX 패턴을 일관되게 적용해야 함

### 임시 우회

- `entry_new`: tags 없이 생성 후 (현재 N0072가 이 상태) 향후 CLI로 tag 부여 (가능 여부 확인 필요)
- `bundle`: depth 생략 (default 사용)
