## Phase C — `escalated_write` 응답 필드 + 🚨 시각 태그

write tool이 `confirm=true`로 guarded origin(`FallbackGlobal | CwdSearchHome`)을 통과한 경우, 응답에 `escalated_write: true` 필드 + 응답 텍스트 prefix에 "🚨 GLOBAL_WRITE_EXECUTED".

근거: gemini r0014 권고 (agent 자기 출력 관찰) — 가드 통과는 silent 성공이 아니라 시각적으로 강조해야 후속 agent가 의도된 escalation임을 인지.

구현 위치 후보:
- (a) `vault_meta()` 확장: `is_write: bool` + `confirmed: bool` 파라미터 추가
- (b) 7개 write 호출 사이트에서 `escalated_write` 필드 직접 inject — 기존 `result.as_object_mut().unwrap().extend(...)` 패턴 재사용

기본 선택: **(b)**. `ensure_write_confirmed`가 통과한 직후 호출 사이트에서 `if matches!(res.origin, FallbackGlobal | CwdSearchHome) { result["escalated_write"] = true; }` 한 줄. 그러나 7곳 중복 — 새 helper `mark_escalated_if_needed(&mut serde_json::Value, &VaultResolution, bool)` 추출 권고.

응답 텍스트 prefix는 별 표면: Out wrapper에 `text_prefix` 같은 필드 추가하거나, 응답 객체에 `warning_text` 필드. 두 방식 모두 호환 — 기본 선택은 응답 JSON에 `warning: "🚨 ..."` 필드 추가 (구조 더 간단).

검증:
- guarded origin + confirm=true write → `escalated_write: true` + `warning` 필드 동봉
- guarded origin + confirm=false → reject (Phase B 기존 동작, 회귀 0)
- 정상 origin(ExplicitPath 등) + write → 두 필드 없음 (호환)

이미 `vault_origin` 필드가 부분 구현(`vault_meta`). N0038 r0011의 정합 항목 — enum string set 표준화 + 응답 contract 명세 문서.

string set (현재 코드 기준 7 + 1):
- `explicit_path` / `explicit_global` / `alias:<name>` / `env_var` / `cwd_search` / `cwd_search_home` / `fallback_global`
- (Alias variant는 dynamic — `alias:` prefix + alias 이름)

N0070 PLAN N0038 r0011은 `session_local` / `primary` 도 언급했지만 enum에 없음 — scope 최소화 정신으로 **(a) 기존 7+1 string set만 stable contract로 고정**, session/primary는 v0.6+ 이후 enum 확장 시 추가.

작업:
