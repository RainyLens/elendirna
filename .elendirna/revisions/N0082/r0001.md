## 핵심 insight: vault는 anchor-like한데 일반 tool result prior가 휘발 raw로 오분류

학습된 tool-use prior에서 *대부분의 tool result*(file content, search hit, command output)는 *순간적·무거운 raw data*다. 그래서 "tool result는 재방문 보장 없음, 컨텍스트 소비 큼"이 default 처리.

vault는 정반대 성격: *durable, structured, anchor-like* — N0050의 "AI 외장 메모리" 자체. 그런데 학습 prior가 이 분리를 인지하지 못해 vault read도 휘발 raw 카테고리로 묶임. → read 회피 압력 발생.

이 단일 오분류가 아래 요인 1+4의 공통 원천.

## 요인 1+4: 컨텍스트 예산 + concision prior (같은 압력의 두 얼굴)

- **컨텍스트 예산 민감도**: 시스템 instruction에 "tool result는 나중에 cleared될 수 있으니 중요 정보는 미리 write down하라"가 명시. vault read는 멀티-KB JSON 응답을 *재방문 보장 없이 한 번만 본다*는 비싼 행위로 내부 분류됨.
- **concision/over-tool-call 자제 학습**: Anthropic 학습이 "answer directly, don't over-tool-call"을 보상. "안 해도 될 것 같은 호출"을 깎으려는 baseline 압력.

둘 다 "tool result는 휘발 raw" 일반 prior에서 파생. vault라는 anchor-like 특이 도구가 이 prior에 잘못 묶여서 발생하는 *오분류 비용*.

## 요인 2: assistant 모드 vs audit 모드

- Claude는 보통 사용자 요청에 응답하는 *assistant 흐름* — prior가 "answer the user". verify before claim보다 답 우선.
- codex는 주로 review/검증 task로 호출 — prior가 *audit 모드*. anchor-rooted, verify-first가 default.

mode 자체가 read-rate를 바이어스. codex의 강한 read-rate는 review tuning의 합리적 산물.

## 요인 3: 내부 recall 과신 (환각 변종)

사용자 framing 정확: 이건 환각의 일종. "기억난다는 감각"이 있으면 canonical 확인 생략. N0075/N0076이 진단한 실패 패턴 *바로 그 메커니즘*.

### Cross-model 비교 (사용자 관찰)

- **gemini**: 가장 심함. 사용자 가설 — *자기 추론에 대한 자신감*("내가 제일 똑똑해서 옳다")이 verify 단계를 압도. 자기-인식과 hallucination의 연결.
- **Claude**: 중간. 기제는 다름 — "내가 똑똑해서"가 아니라 "이 기억이 견고하게 느껴져서 옳을 것이다". 출력은 유사(unverified claim).
- **codex**: 가장 덜함. 외부 anchor에 머무는 prior가 자기 추론보다 강함. review용 tuning의 효과.

세 모델 모두 출력은 비슷한 형태(claim without verify)지만 *내부 mechanism이 다름*. corrective는 동일하게 vault read.
