## Delta

[Change] 2026-05-18 발현. Claude Desktop 호스트에서 elendirna MCP 서버가 무한 재시작 루프에 빠짐. v0.5.0→v0.5.4 업그레이드(N0067 r0004)의 후속 회귀.

## 증상
desktop MCP 로그 패턴 (2026-05-18T04:38:51 이후):
1. `Server transport closed unexpectedly` (이전 정상 세션 종료)
2. desktop이 즉시 elf serve --mcp 재spawn
3. elf process stderr: `[elf] vault 없음 — 글로벌 vault 자동 생성: C:\Users\keyst`
4. elf process stderr: `{"code":"E3002","error":"already_initialized","message":"이미 vault가 초기화되어 있습니다: C:\\Users\\keyst"}`
5. elf process exit (비정상) → transport close → desktop 재spawn → 4번부터 무한 루프

elendirna MCP 도구만 사용 불가. Desktop UI / 다른 MCP는 멀쩡 (localvault MCP는 정상 작동 — D:\Work\elendirna를 cwd_search로 잘 잡음).

## 인과 사슬
- `elf serve --help`: `--vault` 미지정 시 기본 동작 = "현재 디렉터리에서 탐색 → 없으면 글로벌 vault 자동 생성"
- Claude Desktop이 spawn하는 elf process의 cwd가 home도 vault도 아닌 위치 (desktop 앱 path 추정)
- cwd 탐색 실패 → 자동 생성 branch 진입 → home(C:\Users\keyst)에 글로벌 vault 생성 시도
- home에는 이미 글로벌 vault 존재 → `elf init` 의미 호출이 E3002 `already_initialized`
- 이 실패가 process exit code 비정상으로 전파 → desktop transport close 인식 → 재spawn 루프

기존 `elf serve --mcp` config(args에 vault 명시 없음, env 비어있음)에서 v0.5.0은 fallback path 채택 후 process 살아있었지만, v0.5.4는 auto-init이 실패하면 process를 죽임. 즉 silent global write 가드 강화 부수 효과.

## Fix (적용 완료)
`%APPDATA%\Claude\claude_desktop_config.json`의 elendirna MCP args에 `--global` 추가:
```
"args": ["serve", "--mcp", "--global"]
```
효과: `--global`이 cwd 탐색 branch 자체를 skip하고 곧장 `~/.elendirna/` 사용. auto-init trigger 안 됨.

백업: `claude_desktop_config.json.bak.20260518` (2114 bytes).

회복은 Claude Desktop 재시작(또는 desktop의 MCP reload) 시점에 발효. 본 entry는 fix 적용 직후 작성 — desktop 재시작은 사용자 본인이 수행 예정.
