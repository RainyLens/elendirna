## Decision: init context 분리

진입 함수에 context enum 1개 추가:
- `Explicit` (CLI `elf init` 명시 호출, 또는 향후 MCP에 명시 init 도구 추가 시) → 기존 동작 유지: `already_initialized` error 반환, exit code 비정상
- `Fallback` (MCP `serve`의 auto-init, CLI 다른 명령의 vault detection 실패 시 fallback) → warning + 기존 vault 채택, process 계속

분리 축이 entry point(CLI vs MCP)가 아니라 *명시 init vs fallback init*인 이유: CLI의 다른 명령(`elf entry new` 등)이 vault detection 실패 시 같은 fallback path 트리거할 가능성 있음. entry point 이분법은 그 경로를 cover 못 함. 호출 의도(사용자가 init을 의도했나, vault 확보를 의도했나)가 정확한 축.

## Warning 메시지 phrasing (사용자 제안)

> "기존 vault가 있으니 내용 섞임에 유의"

이 phrasing의 강점:
- silent 함정 회피 — 사용자/agent가 *어느 vault에 쓰고 있는지* 인지할 기회 제공
- 시맨틱 정직 — "auto-init이지만 실제로는 기존 vault 채택"임을 명시
- N0067 r0001 원 보고(silent global write)의 본질적 함정 패턴을 표면화

응답 구조 후보(MCP 한정):
- stderr 로그 한 줄 (이 phrasing)
- session_start 응답의 `warning` 필드(v0.5.4에 이미 존재)에 동일 메시지 동봉
- `vault_origin`은 기존 그대로 (`cwd_search` / `fallback_global` 등) — 새 origin 신설 불필요

## Scope

- init 진입 함수 1개에 `InitContext { Explicit, Fallback }` enum 파라미터 추가
