### 결정 2-sub (추가 필요) — 기존 `warning` (escalated_write)와의 관계

(3) 채택의 자연스러운 함의로 추가 결정 1건 발생. 둘 중 선택 필요:

**(3a) 통합** — 기존 `warning` (string, [src/mcp/mod.rs:112-132](src/mcp/mod.rs))을 `warnings[]` array에 흡수
  - pros: contract 단일화. "warnings는 array"라는 명확한 spec. "원래 있었어야 맞다" 원칙과 정합
  - cons: 7개 write tool 응답의 `warning` 필드명 → `warnings[]`로 일괄 migrate. backward compat break (downstream agent가 `warning` string 파싱 중이면 영향). v0.5.4 응답 contract([CHANGELOG.md L23-29](CHANGELOG.md)) 변경
  - 메시지 모양: `warnings: ["🚨 GLOBAL_WRITE_EXECUTED — ...", "기존 vault가 있으니 내용 섞임에 유의: ..."]` (해당 시 두 개 동시 inject 가능)

**(3b) 공존** — `warning` (string, escalated_write 전용 = "실행됨" 보고) + `warnings[]` (array, 시점성 caution = "주의 필요") 분리 유지
  - pros: 의미 분리 명확. escalated_write의 🚨 톤은 "이미 실행됨"의 사실 보고, warnings[]는 사용자 표현 그대로 "사용에는 주의 필요"의 향후 지시. 시맨틱 직교
  - cons: 같은 vault_meta에 `warning` + `warnings[]` 두 필드 — 인지 부담. agent가 둘 다 읽어야 함

권고: **(3a) 통합**이 사용자의 "원래 있었어야 맞다" stance와 정합. backward compat break는 v0.5.5 patch bump로 changelog에 명시. 단, escalated_write의 🚨 marker는 array 원소에 보존(`warnings: ["🚨 ..."]`)해서 시각 강조 유지.

(3b)도 valid — "실행됨 보고" vs "주의 필요"의 시맨틱 직교를 더 중시한다면 (3b). 본 결정 한 번 더 신호 필요.
